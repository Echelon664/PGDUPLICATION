# SDCounty HHSA Program Guide

A fast, searchable policy engine and AI assistant for the County of San Diego Health and Human Services Agency (HHSA) public guides:
* **CalFresh (SNAP)** — [Folder 542](https://file.sandiegocounty.gov/HHSAPublicSite/Section?FolderId=542)
* **CalWORKs (TANF)** — [Folder 448](https://file.sandiegocounty.gov/HHSAPublicSite/Section?FolderId=448)
* **Medi-Cal (Medicaid)** — [Folder 599](https://file.sandiegocounty.gov/HHSAPublicSite/Section?FolderId=599)

---

## Features

1. **Local PDF Serving**: County PDFs are stored in `data/pdfs/` and served by the app (`/pdfs/<file name>.pdf`), so users view documents in their browser without leaving the site. An entry without a stored County PDF (`"source_missing": true` in `data/documents.json`) is shown as "County document not bundled", links to the County site, and is never used as an AI source.
2. **Dual Search Modes**:
   * **Ask AI (RAG)**: Natural language question-answering with citations to official manual chapters and documents.
   * **Policy Search (SQLite FTS5 BM25)**: Instant keyword, phrase, and code lookup (e.g. `63-151`, `SAR 7`, `IRT`) with Porter stemming, section-number matching, and acronym expansion (`WTW`, `ABAD`, `SUA`, `SNAP`, `Medicaid`).
3. **Program Filtering**: Filter searches across All Programs, CalFresh only, CalWORKs only, or Medi-Cal only.
4. **Official Links & Disclaimers**: Includes secondary links to the County's public portal for reference, with clear disclaimers that this is an independent community reference tool.
5. **Zero Heavy Infrastructure**: Built with pure Python standard library support (`server.py`) and FastAPI (`app.py`), ready for 1-click cloud deployment.

## Quickstart (Local)

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. (Optional) Run Crawler
To see what the San Diego County portal currently lists:
```bash
python3 crawler.py
```
This writes raw search hits to `data/crawl/documents.raw.json` for review. It
does not modify `data/documents.json` (the curated catalog the app serves) and
does not create PDFs. After changing `data/documents.json`, regenerate the page
with `python3 generate_preview.py`.

### 3. Build the Search Index (Optional)
The FTS5 index builds automatically on first search. To rebuild it and run sample queries:
```bash
python3 search_engine.py
```
To compare the legacy BM25 engine with FTS5:
```bash
python3 evaluate_search.py
```

### 4. Start the Web Server
```bash
uvicorn app:app --reload --port 8000
```
Open your browser to [http://localhost:8000](http://localhost:8000).

## Search Engine

`search_engine.py` uses SQLite FTS5 from the Python standard library. It builds
`data/search.db` from `data/documents.json` and rebuilds automatically when the
documents file changes. The query layer adds:

* Porter stemming (`student` / `students`, `eligibility` / `eligible`)
* Exact and prefix section-code matching (`63-151`, `10-005`)
* Program and acronym expansion (`WTW`, `ABAD`, `SUA`, `SAR`, `SNAP`, `Medicaid`)
* Phrase queries, per-document deduplication, and title phrase boosts

No extra services or Python packages are required.

## Document Dates

Each entry shows a date taken from its own PDF, so readers can tell how current
it is. `python3 pdf_dates.py` reads the date printed in the document header
(revision, issue or effective date) and, for documents that print none, the date
stored in the PDF file ("PDF file date"). It writes `pdf_date` and
`pdf_date_label` to `data/documents.json`; run `python3 generate_preview.py`
afterwards. `county_apply.py` stamps new and replaced entries automatically.
The County's own posting date is shown alongside as "Posted on County site".

## County Source Check

`county_sync.py` compares the stored PDFs with what the County currently
publishes under CalFresh, CalWORKs and Medi-Cal at
<https://file.sandiegocounty.gov/HHSAPublicSite/>. The report is shown at
`/sync` on the site.

| Scan | What it does | Time |
|---|---|---|
| `quick` | Reads the County's file list and compares file IDs and publish dates with the last full scan | about a minute |
| `full` | Also downloads every County file and compares its SHA-256 with the stored PDF | 10-20 minutes |

```bash
python3 county_sync.py full     # or: quick
python3 -m unittest test_county_sync
```

Each County file lands in one group: identical, changed at the County, on the
County site but not stored here, stored under the wrong catalog entry, or could
not be checked. Catalog entries no County file matches are listed as "stored
here, not on the County site". Only a full scan with no differences reports
"in sync".

Things to know:

* The scan is report-only. It never changes `data/documents.json` or `data/pdfs/`.
* To apply a full scan's findings, run `python3 county_apply.py --dry-run`, then
  `python3 county_apply.py [--remove-stale]` and `python3 generate_preview.py`.
  It downloads changed and missing County files, adds or fills catalog entries,
  records each entry's County file ID, direct link and publish date, and (with
  `--remove-stale`) drops entries the County no longer publishes. Summaries of
  new or replaced documents are copied from the document's own Purpose or
  Background paragraph; review them afterwards. Needs `pypdf` and `cryptography`.
* The County re-stamps the PDF trailer `/ID` on some downloads, so that field is
  ignored when hashing. Everything else in the file must match byte for byte.
* Scans can be started from `/sync` only when the `ADMIN_TOKEN` environment
  variable is set, and only with that token. Without it the page is read-only.
  A full scan makes about 900 requests to the County, so it is not public.
* Results are saved in `data/county_sync/` (`report.json`, `manifest.json`).
  On hosts with an ephemeral disk, a scan run from the page is lost on redeploy;
  commit the files from a local run to ship a report with the image.
* `COUNTY_SYNC_DELAY` sets the pause between County requests (default 0.15 s).

## Enabling AI Answers

The "Ask Policy AI" feature is configurable through environment variables and
falls back to a built-in "Direct Manual Evidence" answer when no provider is set.

| Variable | Description |
|---|---|
| `AI_PROVIDER` | `ollama`, `openai` (any OpenAI-compatible API), or unset to disable |
| `AI_BASE_URL` | Provider base URL (defaults: `http://localhost:11434` for ollama, `https://api.openai.com/v1` for openai) |
| `AI_MODEL` | Model name (defaults: `llama3.2` for ollama, `gpt-4o-mini` for openai) |
| `AI_API_KEY` | Required for the `openai` provider |
| `AI_TIMEOUT` | Request timeout in seconds (default 60) |
| `AI_RATE_LIMIT_PER_MIN` | LLM calls allowed per visitor per minute (default 6) |
| `AI_RATE_LIMIT_GLOBAL_PER_MIN` | LLM calls allowed per minute across all visitors (default 30) |
| `AI_MAX_QUESTION_CHARS` | Longest accepted question (default 500) |

Visitors over the limit still get the built-in "Direct Manual Evidence" answer;
only the LLM call is skipped. The limits are per process and held in memory.

### Local Ollama (100% Free & Local)
```bash
ollama run llama3.2:3b
AI_PROVIDER=ollama uvicorn app:app --reload --port 8000
```

### Hosted OpenAI-compatible API (Groq, OpenAI, Together…)
```bash
AI_PROVIDER=openai \
AI_BASE_URL=https://api.groq.com/openai/v1 \
AI_MODEL=llama-3.3-70b-versatile \
AI_API_KEY=... \
uvicorn app:app --port 8000
```

Set the same variables in your hosting platform's environment (Railway, Render,
Fly, etc.). If no provider is configured, `/api/ask` returns the built-in
"Direct Manual Evidence" answer with no LLM.

## Public Web Hosting Deployment

The app ships in a single container that builds the search index automatically
on first request. The `data/pdfs/` folder and `data/documents.json` are baked
into the image; `data/search.db` is generated at startup (and git-ignored).

### Build and run locally

```bash
docker compose up --build
# or without compose:
docker build -t sdcounty-hhsa .
docker run -d -p 8000:8000 --restart unless-stopped sdcounty-hhsa
```

The container listens on `$PORT` (default 8000) and exposes a `/health`
endpoint for orchestrator health checks.

### Hosting platforms (fastest)

Any platform that builds a Dockerfile works out of the box:

* **Railway** — `railway up` or link the repo; it builds the Dockerfile and
  issues an HTTPS URL.
* **Render** — new **Web Service** → **Build and Deploy from a Git repo**,
  runtime **Docker**; it reads the Dockerfile automatically.
* **Fly.io** — `fly launch` (pick the existing Dockerfile) then `fly deploy`;
  gives a global edge + automatic TLS.

For all three: no start command is needed — the Dockerfile `CMD` is used. Make
sure the service port is set to **8000** (or set the `PORT` env var).

### Self-host on a $4–6 VPS (Hetzner / DigitalOcean / Oracle)

```bash
# on the server
git clone <repo-url> && cd <repo>
docker build -t sdcounty-hhsa .
docker run -d -p 8000:8000 --restart unless-stopped --name hhsa sdcounty-hhsa
```

Then put HTTPS in front with Caddy (one line):

```bash
# Caddyfile
your-domain.com {
    reverse_proxy localhost:8000
}
```

Run Caddy in a container (`docker run -d -p 80:80 -p 443:443 -v $PWD/Caddyfile:/etc/caddy/Caddyfile caddy`)
and it provisions Let's Encrypt certificates automatically.

### Notes for production

* The bundled PDFs and documents are static data; rebuild the image when
  `data/` changes. The search index always rebuilds from `documents.json`.
* "Ask AI" uses whatever `AI_PROVIDER` is configured (see above) and falls back
  to the built-in "Direct Manual Evidence" answer otherwise. With a paid API key,
  keep the rate limits on: `/api/ask` is public.
* Single-process uvicorn is fine for this workload. For heavier traffic, run
  multiple workers (`uvicorn app:app --workers 4`) behind a load balancer; the
  SQLite index is read-only per process. Rate limits are counted per worker.
